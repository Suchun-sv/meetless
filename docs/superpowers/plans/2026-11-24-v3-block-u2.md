# Meetless v3 Phase 1, Block U2 (Needs and Collaboration) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the needs board (rounds and lineage), the need drawer with its handoff block, the handoff modal, the link-for-agent modal, and 「待确认」 with conflicts, detected items, questions and agent proposals. Everything is computed from the live, event-sourced project record and works for real between two users.

**Architecture:** Derived data lives in three pure, tested modules: `needs/model.ts` (board, cards, lineage, drawer lists), `collab/model.ts` (the handoff state view, command builders, people and due choices, the prompt and the context preview) and `collab/confirm.ts` (the 「待确认」 items and their commands). React components render those results and submit only through `useApp().submit`. Other blocks' UI is reached only with `go`, `openNeed` and `openOverlay`. The context preview is always built from `shareableView(live)`, so private items never appear in a link, a prompt or a preview.

**Tech Stack:** TypeScript 7 strict, React 19, Vite 8, vitest 5 (server-side markup tests, no jsdom), Playwright 1.65, Electron 45.4.1 through the Xvfb container, and `@meetless/core`, `@meetless/i18n` as frozen by Phase 0.

**Spec:** `docs/superpowers/specs/2026-11-24-meetless-v3-design.md` (binding, in Chinese), §5 协作, §6 rows 需求, 需求详情抽屉, 交接弹窗 / 链接弹窗 and 待确认, §7, §10. Names come from `docs/superpowers/plans/2026-11-24-v3-contract.md`, and what exists at the start comes from `docs/superpowers/plans/2026-11-24-v3-phase0-base.md`. The behaviour spec is the prototype, `design/claude-design-v3/`.

## Review Focus

1. **Reminded, then revised again.** The sender asks for a refresh at v2, then revises the need to v3. The warning must come back at v3 with 「提醒刷新」 available again. Test: Task 4 `reminding hides the warning until the need is revised again`.
2. **A private or invisible need reached by route or overlay.** Examples: chat opens the hand-off modal for a private need, or the route keeps a `needId` after the user changes. The drawer shows `dr.missing` and crashes nothing. The hand-off modal shows `ho.privateFirst` and no Send button, and the link modal shows `lk.privateFirst` and no prompt. Tests: Task 5 `an unknown need id renders dr.missing`, Task 7 `a private need gives no prompt`, Task 8 `a private need cannot be handed off`.
3. **A delegated conflict.** After Alex hands the N1 decision to Lin, Alex's panel shows 「等 Lin 决定」 with no buttons and Lin's shows it with `cf.whyDelegated`. Once it is resolved, the decision hand-off no longer shows on the N1 card. Tests: Task 2 `shownHandoff skips declined handoffs and resolved conflict decisions`, Task 9 `a delegated conflict moves to the new decider`, Task 10 `the delegator sees Waiting for, the delegate sees the reason`.
4. **Nobody to hand off to, or members without a role.** In a project with only me, the modal shows `ho.nobody` and a disabled Send button. Members without a role are listed under `ho.noRole`. Tests: Task 4 `handoffPeople groups by role, lists role-less members last, never me`, Task 8 `a project with only me shows ho.nobody`.
5. **A project without rounds, or needs without a round.** The board shows `board.noRounds` and a trailing 「未排期」 column, and no need disappears. Tests: Task 2 `needs without a round go to a trailing Unscheduled column`, Task 3 `a project without rounds`.
