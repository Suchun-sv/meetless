# Meetless v3 Phase 1, Block U1 (Shell and Dashboards) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Phase 0 placeholders in `renderer/{shell,dash,chat,setup}` with the v3 prototype's sidebar and project tree, the top bar, the project-agent composer (rule-based retrieval answers, suggestion chips, adding cards by asking), the project and Home dashboards, invite and dev-token sign-in, new project, members and roles with invites, rounds setup, and the Agents page.

**Architecture:** Every page reads the signed-in user's `live` state through core queries (contract §2) and writes only through `useApp().submit(type, payload)` or `useApp().api(name, input)`. Each folder keeps its derived data and its command builders in a pure, tested `model.ts`. The components stay thin, and component tests render them statically (`renderToStaticMarkup`, no jsdom). Clicks and multi-client behaviour are tested in two Playwright specs against the real server. S's routes (invites, tokens, agent calls, setup, `inputs.import`) are reached through `api()`. Until S merges they return `HTTP_404`, and the UI shows that error through `errorText`; it never fakes an answer.

**Tech Stack:** React 19, TypeScript 7 strict, Vite 8, vitest 5 (static markup), Playwright 1.65, Electron 45.4.1 (Xvfb only). Core `@meetless/core`, `@meetless/api`, `@meetless/i18n`.

**Spec:** `docs/superpowers/specs/2026-11-24-meetless-v3-design.md` (binding, in Chinese; §5 "界面", §6 page table, §7, §8.7, §8.8). Names come from `docs/superpowers/plans/2026-11-24-v3-contract.md`. The starting state is `docs/superpowers/plans/2026-11-24-v3-phase0-base.md` (Tasks 10–12). Behaviour comes from the prototype `design/claude-design-v3/` (entry `Meetless Needs Prototype v3.html`). Each task names the prototype file it ports.

## Review Focus

1. **An input imported from the chat while 「仅自己」 is on.** The person expects the input, and every need detected from it, to stay private. Test: Task 3 `importCommand` with `priv: true` gives `private: true`. Task 12 checks that Zhou's page and cache never contain the text.
2. **A brand-new account with no projects, or a new project with one member, no roles and no rounds.** The person expects empty states with a way forward, not a blank page or a crash. Tests: Task 2 (empty sidebar), Task 6 (no current round shows `pg.noRound` and the rounds link; the setup prompts appear), Task 7 (Home with zero projects shows `pj.empty` and `nav-new-project`).
3. **A round whose due date is before its start, or an edit to a delivered round.** The person expects an inline reason before anything is sent, and delivered rounds to be read-only. Test: Task 10 `roundDraftError`. The render test checks there are no edit controls on a delivered round.
4. **Invite sign-in with a lower-case or padded code, an empty name, a used code, or a server with no invite route yet.** The person expects a visible reason that names the URL. Tests: Task 8 `signInMessage` (HTTP_404 maps to `error.NOT_IMPLEMENTED` with the URL; INVITE_USED) and `inviteFormError`. Task 13 e2e redeems a lower-case code with spaces.
5. **Pressing Enter while an IME composition is open, sending only whitespace, or clicking "Import as input" twice (or again after a reload).** The person expects nothing to be sent, and one input. Tests: Task 3 `shouldSend` (composing, whitespace) and `importCommand`, whose input id `in-<messageId>` is deterministic, so a second import is refused as `ALREADY_EXISTS` rather than duplicated.

### Task 3: Chat model: text and chips to commands

Ports `onSend`, `onChip`, `sendFile`, `addWidget` and the suggestion wiring in `needs3/app.jsx`.

**Files:**
- Create: `apps/desktop/src/renderer/chat/model.ts`
- Test: `apps/desktop/test/chat/chat-model.test.ts`

**Interfaces:**
- Consumes: core `answer`, `suggestions`, `cardsFor`, `handoffStaleness`, `chatMessages`, `RULES_PROVIDER_ID`, `PROJECT_CARDS`, `HOME_CARDS`, `clip`, types `AgentReply`, `AgentScope`, `Suggestion`, `CardId`, `EventType`, `EventPayloads`; `addCardPayload` (`dash/model.ts`, signature in Task 5). Step 3 writes it, and Task 5 adds its tests and the other dashboard helpers.
- Produces:
  - `type U1Command = { [K in EventType]: { type: K; payload: EventPayloads[K] } }[EventType]`
  - `agentScope(scope: 'home' | Id): AgentScope`
  - `shouldSend(text: string, composing: boolean): boolean`. False while an IME composition is open, or when the text is only whitespace.
  - `chipsFor(s: State, me: Id, scope: 'home' | Id, onDash: boolean, today: IsoDate): Suggestion[]`. This is `suggestions(s, me, agentScope(scope), today, onDash ? { dashboardCards: cardsFor(s, me, scope).cards, pool: scope === 'home' ? HOME_CARDS : PROJECT_CARDS } : {})`.
  - `chipLabel(t: Translator['t'], s: State, chip: Suggestion): string`. The labels are `sg.stale {need, who}`, `sg.toMe {who}`, `sg.conflict {n}`, `sg.proposal {n}`, `db.add {name: t('w.<card>')}` and `sg.ask.<prompt>`. `need` is the need's code and `who` is `displayName`.
  - `cardReply(card: CardId): AgentReply`, which is `{ answer: { intent: 'addCard', card, cites: [] }, provider: RULES_PROVIDER_ID, simulated: true }`.
  - `staleReply(s: State, me: Id, handoffId: Id): AgentReply`, with intent `stale` and the one item built from `handoffStaleness`.
  - `sendCommands(s: State, me: Id, scope: 'home' | Id, text: string, today: IsoDate, now: IsoTime, messageId: Id): U1Command[]`. The first command is always `chat.asked { messageId, scope, text, reply: answer(s, { userId: me, scope: agentScope(scope), text, today }) }`. When the intent is `addCard`, the second command is `dashboard.set` from `addCardPayload(cardsFor(s, me, scope), scope, card, now)`.
  - `type ChipOutcome = { commands: U1Command[]; open?: { projectId: Id; needId: Id }; overlay?: Overlay }`
  - `chipOutcome(s: State, me: Id, scope: 'home' | Id, chip: Suggestion, label: string, today: IsoDate, now: IsoTime, messageId: Id): ChipOutcome`. The outcome per chip:
    - `stale`: `[handoff.refresh_requested { handoffId }, chat.asked { text: label, reply: staleReply }]`;
    - `toMe`: `open`;
    - `conflict` and `proposal`: `overlay { kind: 'confirm', projectId }`;
    - `addCard`: `[chat.asked { text: label, reply: cardReply(card) }, dashboard.set]`;
    - `ask`: `sendCommands(..., label, ...)`.
  - `inputTitleFrom(text: string): string`. It takes the first non-empty line, strips leading `#`, `>`, `-`, `*` and spaces, and clips it to 40 characters with `clip`.
  - `importCommand(a: { projectId: Id; messageId: Id; text: string; priv: boolean; today: IsoDate }): ApiRequest<'inputs.import'>`. This is `{ projectId, inputId: 'in-' + messageId, title: inputTitleFrom(text), kind: 'md', blobHash: null, text, from: null, date: today, private: priv }`.
  - `fileImport(a: { projectId: Id; name: string; priv: boolean; today: IsoDate; inputId: Id }): { kind: InputKind; readAsText: boolean } & Omit<ApiRequest<'inputs.import'>, 'blobHash' | 'text'>`. The extension sets the kind: `.md`/`.markdown` is `md`, `.txt` is `txt`, `.docx`/`.doc` is `docx`, `.pdf` is `pdf`. `readAsText` is true for md and txt. The other kinds go through `uploadBlob` first.
