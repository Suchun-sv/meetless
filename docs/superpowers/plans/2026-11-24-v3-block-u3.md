# Meetless v3 Block U3 (Inputs and Artifacts) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the inputs page (import, write Markdown), the artifacts page (OnlyOffice read-only view with a LibreOffice fallback), real capture of the latest changes (local git, Overleaf via git URL, Notion via MCP and a page link, uploaded versions), the activity stream, the deliveries timeline, and the OnlyOffice container script.

**Architecture:** The four pages are React views in the U3 folders. Each folder has a pure, tested `model.ts`; the components stay thin, because component tests render static markup only. Capture runs in the client process (`CaptureService`, `packages/client/src/capture*`), behind bridge methods in the `// --- U3 capture` sections. It reads the sources and matches records to needs with core `matchNeed`. It records only matched items, as `work.recorded { capture: true, autoLinked: true }`, through the node's own `submit`. Captures are never progress. Secrets (the Overleaf token and Notion OAuth tokens) stay in 0600 files in the client data dir. They never reach the server, the event log, the renderer or the logs. OnlyOffice is embedded from the config S signs (`office.config`). Any failure falls back to the LibreOffice page images, and the UI names the reason.

**Tech Stack:** pnpm 12.23, TypeScript 7 strict, vitest 5, React 19, Vite 8, Electron 45.4.1, Playwright 1.65, node:child_process git, `@modelcontextprotocol/sdk` (client and, in tests, server), OnlyOffice DocumentServer 8.3 (`onlyoffice/documentserver:8.3`), PostgreSQL 16 (`meetless-pg`).

**Spec:** `docs/superpowers/specs/2026-11-24-meetless-v3-design.md` (binding, Chinese). Names come from `docs/superpowers/plans/2026-11-24-v3-contract.md` (the contract). What exists at the start is in `docs/superpowers/plans/2026-11-24-v3-phase0-base.md`. The UI spec is `design/claude-design-v3/`. Executors read all four.

## Review Focus

1. **User content that carries dot characters** (a Word list "• 支持导出", a commit subject "fix · export", a Notion bullet). Expected: no dot reaches the screen or a stored capture. Pinned in Task 1 (`captured text never contains a dot character`) and Task 8 (`renders paragraphs and extracts through noDots`).
2. **A capture that touches private material** (a private artifact, or a commit that matches my private need, and then a teammate who captures the same commit). Expected: the capture is private to me; the teammate's capture gets its own id and never collides with, or reveals, mine. Pinned in Task 1 (`a capture linked to a private need, or read from a private artifact, is private`; `ids are deterministic and salted by privacy`).
3. **Capture run twice** (a double click, no new commits, the same Notion page). Expected: no duplicate rows, and the user is told "nothing new". Pinned in Task 1 (`a second run with no new commits records nothing`), Task 7 (`the capture button is disabled while a run is in flight`) and Task 11 (`capturing again records nothing new`).
4. **The Overleaf token**. Expected: it is typed into a plain text field that clears on save, and it never appears in `.git/config`, git argv, the log, an event or a bridge result. Pinned in Task 2 (`the token never lands in the clone, the log or a bridge result`) and Task 7 (`the token field is a plain text input`).
5. **OnlyOffice configured but down** (api.js 404, slow script, an `onError` from the editor, or the container cannot reach the server). Expected: the LibreOffice fallback with the reason shown, or for a PDF the note plus the original file; never a blank pane. Pinned in Task 6 (`officeStep falls back on script failure, timeout and editor error`) and Task 11.

## Decisions this plan makes

- **Capture runs in the client process.** It is reached through `bridge.captureRun` (contract §4 lists "run capture" there), so U2's drawer button 「捕获最新」 (prototype `needs3/board.jsx:170`) can call `bridge.captureRun({ projectId, needId })` without importing U3 code.
- **Only matched records are recorded.** An unmatched capture would become an "unlinked" question for its author (core `questions`), so one run would flood 「待确认」. The run result reports how many records were read.
- **Work ids are deterministic.** `captureWorkId(salt, artifactId, key, needId)`, where the salt is the project id for shared results and the user id for private ones. The command id equals the work id.
- **Matching per source.**
  - Code repos match the commit subject.
  - Overleaf matches the subject, unless it is Overleaf's default `Update on Overleaf.`, and also each added line of `.tex`/`.bib`/`.md`/`.txt` files.
  - Notion matches each paragraph of the page.
  - Uploaded versions match the version note and each LibreOffice text block.
- **Local or `file://` git URLs for Overleaf** are accepted only on the `dev-bridge` host (tests use a local bare repo). Electron accepts only `https://git.overleaf.com/<id>`. `MEETLESS_NOTION_MCP_URL` is honoured only on `dev-bridge`.
- **Opening the Notion OAuth page.** The renderer calls `window.open(authorizeUrl)`. The existing `setWindowOpenHandler` in `main.ts` already calls `shell.openExternal`, so `main.ts` gains only a subframe rule.
- **PDF without OnlyOffice:** a note plus the original file. LibreOffice previews cover pptx and docx only.
- **Hypothesis extracts use `tone-info`.** Violet stays for rule output.
- **Before S merges**, md and txt import through `importTextLocally()` (contract §10), and docx and pdf go only through `api('inputs.import')`, which shows `errorText(code)` until S ships it.

- Produces (`capture/types.ts`, re-exported from the bridge U3 section with `export { … } from './capture/types'`):

  - `type CaptureSourceKind = 'repo' | 'overleaf' | 'notion' | 'upload'` (code maps to repo; pptx, docx and pdf map to upload).
  - `interface CaptureSource { artifactId: Id; kind: CaptureSourceKind; ready: boolean; code: CaptureCode | null; repo: RepoInfo | null; syncedAt: IsoTime | null; lastRunAt: IsoTime | null }`
  - `interface CaptureStatus { sources: CaptureSource[]; overleafToken: boolean; notion: 'connected' | 'disconnected' }`
  - `interface CaptureRunRequest { projectId: Id; artifactIds?: Id[]; needId?: Id | null }`
  - `interface CaptureRunResult { read: number; recorded: number; queued: number; rejected: { workId: Id; code: string }[]; skipped: { artifactId: Id; code: CaptureCode }[] }`
  - `OVERLEAF_GIT_URL = /^https:\/\/(?:git@)?git\.overleaf\.com\/[A-Za-z0-9]+\/?$/`, `NOTION_PAGE_URL = /^https:\/\/(?:www\.)?(?:notion\.so|[a-z0-9-]+\.notion\.site)\/\S+$/`, `MAX_CAPTURES_PER_RUN = 30`, `CAPTURE_LOG_LIMIT = 50`.
- Produces (`capture/plan.ts`, Node side):
  - `interface CaptureRecord { key: string; src: 'commit' | 'doc'; date: IsoDate; label: string; candidates: string[] }`
  - `captureWorkId(salt: string, artifactId: Id, key: string, needId: Id): Id`. It returns `'cap-' + sha256(salt|artifactId|key|needId)` hex, first 24 characters.
  - `versionRecords(a: Artifact): CaptureRecord[]`. Per version: one record from `note` (key `v:<versionId>:note`, label = version label), and one per `derived.texts[i]` (key `v:<versionId>:b<i>`). `src: 'doc'`, `date` = version date. Empty texts are skipped.
  - `commitRecords(commits: CommitInfo[], extra?: Record<string, string[]>): CaptureRecord[]`. Key = full sha, label = first 7 characters, date = `commit.date.slice(0, 10)`, candidates = `[subject, ...extra[sha]]`.
  - `planCapture(s: State, me: Id, a: Artifact, records: CaptureRecord[], opts?: { needId?: Id | null; max?: number }): CommandInput<'work.recorded'>[]`.
    - Candidate needs are `projectNeeds(s, a.projectId).filter(isOpen)`, or only `opts.needId`.
    - For each record, it takes the first candidate text that `matchNeed` hits, then one command per (record, need).
    - Privacy: `private = a.privateTo !== null || need.privateTo !== null`. The salt is `a.projectId` when shared and `me` when private.
    - It skips ids already in `s.work`, and caps at `opts.max ?? MAX_CAPTURES_PER_RUN`.
    - Payload: `{ workId, projectId, needId, src, text: noDots(clip([a.title, r.label, line].join(SEP), 200)), date, capture: true, autoLinked: true, private }`, with `cmd.id = workId`.
- Produces (`capture/store.ts`):
  - `class CaptureStore { constructor(dir: string); bindings(): Record<Id, { repoId: string }>; bind(artifactId, repoId | null): void; overleaf(artifactId): { repoId: string; url: string; syncedAt: IsoTime } | null; setOverleaf(...): void; lastRun(artifactId): IsoTime | null; setLastRun(artifactId, at): void; secret(name: 'overleafToken'): string | null; setSecret(name, value | null): void }`
  - Files: `<dataDir>/capture/capture.json`, and `<dataDir>/capture/secrets.json` with mode `0o600`. Writes are atomic (tmp file, then rename).
- Produces (`capture.ts`):
  - `class CaptureError extends Error { code: CaptureCode }`
  - `interface CaptureContext { state: State; me: Id; today: IsoDate; submit(cmd: CommandInput): Promise<SubmitResult> }`
  - `class CaptureService`:
    - `constructor(opts: { dataDir: string; repos: GitRepos; host: 'electron' | 'dev-bridge'; log?: (m: string) => void; exec?: GitExec })`
    - `status(s: State, me: Id, projectId: Id): Promise<CaptureStatus>`
    - `bindRepo(artifactId: Id, repoId: string | null): Promise<void>`
    - `run(ctx: CaptureContext, req: CaptureRunRequest): Promise<CaptureRunResult>`
  - `type GitExec = (cwd: string, args: string[], env: Record<string, string>) => Promise<string>` is the injectable git runner. The default uses `execFile('git', …)`, with no shell and `GIT_TERMINAL_PROMPT=0`.
- Produces (bridge, `MeetlessBridge` U3 section; each name is also added to `BRIDGE_METHODS` in its U3 section). Types use inline `import('./capture/types').X`:
  - `captureStatus(projectId: Id): Promise<Result<{ status: CaptureStatus }>>`
  - `captureBindRepo(artifactId: Id, repoId: string | null): Promise<Result<{ bound: boolean }>>`
  - `captureRun(req: CaptureRunRequest): Promise<Result<{ result: CaptureRunResult }>>`
- `ClientNode` U3 section:
  - It creates the service lazily: `this.captureSvc ??= new CaptureService({ dataDir: this.opts.dataDir, repos: this.repos, host: this.opts.host ?? 'electron', log: this.opts.log })`.
  - It builds the context from `await this.snapshot()`:
    - `state` replays the events and skips inapplicable ones, the same rule as the renderer's `safeReplay`;
    - `me` = `session.userId`;
    - `today` = the local `YYYY-MM-DD`;
    - `submit` = `this.submit`.
  - Without a session it returns `{ ok: false, code: 'not_signed_in' }`. A thrown `CaptureError` becomes `{ ok: false, code }`. Methods never throw.

### Task 2: Overleaf source via git, with the token kept on this machine

Design §8.8: 「Overleaf：填项目的 git 地址 … 令牌存在本机 … 不入库、不上传服务端」. Tests use a local bare repo.

**Files:**
- Modify: `packages/client/src/capture/git-source.ts`, `capture/store.ts`, `capture.ts`, `bridge.ts` and `node.ts` (U3 sections)
- Test: `packages/client/test/capture/overleaf.test.ts`

**Interfaces:**
- Consumes: Task 1 `CaptureService`, `CaptureStore`, `GitExec`, `commitRecords`, `GitRepos.register`, `OVERLEAF_GIT_URL`.
- Produces:
  - `overleafUrlAllowed(url: string, host: 'electron' | 'dev-bridge'): boolean`. `OVERLEAF_GIT_URL` is always allowed; an absolute path or `file://` URL is allowed only on `dev-bridge`.
  - `gitAuthEnv(token: string | null): Record<string, string>`. It returns `{}` for null. Otherwise it returns `{ GIT_CONFIG_COUNT: '1', GIT_CONFIG_KEY_0: 'http.https://git.overleaf.com/.extraHeader', GIT_CONFIG_VALUE_0: 'Authorization: Basic ' + base64('git:' + token) }`.
  - `OVERLEAF_DEFAULT_SUBJECT = /^update on overleaf\.?$/i`
  - `addedLines(exec: GitExec, dir: string, sha: string, max = 40): Promise<string[]>`. It runs `git show --format= --unified=0 --no-color --no-ext-diff <sha> -- '*.tex' '*.bib' '*.md' '*.txt'` and keeps `+` lines (not `+++`), trimmed, at least 12 characters long.
  - `CaptureService.setOverleafToken(token: string | null): Promise<void>` stores the trimmed token; `''` or `null` clears it.
  - `CaptureService.syncOverleaf(a: Artifact): Promise<{ repo: RepoInfo; syncedAt: IsoTime }>`.
    - The clone lives in `<dataDir>/capture/overleaf/<sha256(artifactId) first 16 hex>`, created by `git clone --quiet <url> <dir>`; later syncs run `git pull --ff-only --quiet`.
