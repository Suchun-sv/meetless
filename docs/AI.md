# The project agent and DeepSeek

The project agent answers free questions with DeepSeek when the server operator turns it on. Everything
else the agent does stays rule-based: adding a card, importing a pasted text, handing off, stale handoffs,
"what first today", deadlines, the weekly and delivery drafts.

## What is sent, and to whom

A free question goes from the app to the Meetless server (`POST /v1/agent/ask`), never straight to
DeepSeek. The server then sends one chat completion request to DeepSeek
(`MEETLESS_AI_BASE_URL`, default `https://api.deepseek.com`). That request holds:

- the question as typed;
- the asker's display name, today's date, and the project names, current round and member names;
- up to about 14,000 characters (6 to 8k tokens) of the project record, picked by the same keyword
  retrieval the rule answer uses, then the rest of the current round: need codes and titles, status,
  acceptance or expected criteria, the source quote, the last revisions and work, and the matching input
  paragraphs and artifact page text.

The record is built from the asker's own view (`viewFor`). Another user's 「仅自己」 items are never in it.
Nothing is sent for intents, for suggestion chips, or when AI is off.

The answer is in the language of the question: Chinese when it has any Chinese characters, English when it has English words, and the asker's account language when it has only need codes or numbers.

The answer is checked before it is shown. Cite ids the model made up are dropped, and the remaining ones
become the need chips and material chips under the answer. Markdown, bullets and dot symbols are removed.
The reply is stored in the asker's private chat thread like any other answer.

## Content to add

Text given to add rather than asked (需要：1. ... 2. ..., TODO:, a numbered or ；-separated list, several
lines, or anything longer than 80 characters that is not a question) is imported as an input (source 消息)
and its items go to 待确认 / To confirm. Nothing becomes a need until someone accepts it; the reply offers
「全部接受」 and 「去确认」. The composer's 「仅自己」 makes the input, its extracts and the needs they make
private. The New input button and pasted text take the same path.

- The rules decide first. Only a short message with no question shape and no add shape is sent to
  DeepSeek to classify (question, add or command): the message alone, one word back.
- With AI on, the items are extracted by DeepSeek. It gets the message (up to 8,000 characters) and the
  codes and titles of the needs a revision may name (shared needs only, unless the input is private), and
  returns JSON that is checked strictly: known types only, dots removed, at most 8 items, a revision only
  for a listed code. Anything else falls back to the rule detector, which also splits numbered and
  ；-separated lists into separate items. These replies are labelled 「DeepSeek 识别」 or 「规则识别」.

## Turning it on and off

On the server, set:

```
MEETLESS_AI_PROVIDER=deepseek
MEETLESS_AI_KEY=<key>
# optional
MEETLESS_AI_MODEL=deepseek-chat
MEETLESS_AI_BASE_URL=https://api.deepseek.com
MEETLESS_AI_DAILY_TOKENS=2000000
MEETLESS_AI_RATE=20/600
```

Restart the server. Its startup line says `project agent: deepseek (...)` or `project agent: rules only`.
To turn it off, unset `MEETLESS_AI_PROVIDER` or the key and restart. The key lives only on the server. It
is never sent to clients, written to logs or error messages, or committed. Clients learn only
`ai.enabled` from `GET /v1/me`.

The trial server reads these from `~/work/meetless-v3-trial-data/ai.env` (mode 0600) when that file exists.

## What the user sees

- While a question is out, the composer shows 「DeepSeek 正在回答」 / "DeepSeek is answering".
- A generated answer is labelled 「DeepSeek 生成」 / "Generated by DeepSeek". A rule answer keeps 「规则生成」.
- With AI on, the composer says 「问题和相关项目内容会发送给 DeepSeek」 /
  "Questions and related project content are sent to DeepSeek".
- When a free question falls back to the rules, the note under the answer says DeepSeek was unavailable.

## Limits and fallback

| Limit | Default | Past it |
|---|---|---|
| Asks per user | 20 per 10 minutes (`MEETLESS_AI_RATE`) | rule answer |
| Tokens per UTC day, whole server | 2,000,000 (`MEETLESS_AI_DAILY_TOKENS`) | rule answer |
| Time per call | 20 s | rule answer |

The rule answer is also used when AI is not configured, when DeepSeek answers with an error, and when the app
cannot reach the server. The reply's `fallback` field says which (`not_configured`, `rate`, `budget`,
`timeout`, `error`, `offline`).

Each call logs one line on stdout, `[meetless-ai] {...}`, with the user id, ok, status, duration and token
counts. It carries no question, no record text and no key.

## Known gaps

- The daily token count is in memory and starts again at zero after a restart.
- Each question is answered on its own: earlier turns of the thread are not sent (`threadId` is accepted
  and not used yet).
- The answer is not streamed; it appears when the whole reply is in.
